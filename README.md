## 一句话结论

20 所双一流高校官网中，18 所能抓到（90%），但真正能让 Agent 直接用的只有 16 所。
剩下 4 所是**两类完全不同的失败**：2 所是客户端渲染的 SPA（页面本身没内容），
2 所是抓取引擎内部 panic（平台该修的 bug）。

进一步深挖还发现了**第三类更隐蔽的问题**：`links` 字段返回不完整且不可预测
——12 个受测站点里 9 个链接不全，中位缺失 38.9%。

并且与裸 HTTP 抓取对照后发现，对这些非 SPA 站点，
**云平台并没有抓到更多内容**，它的价值在结构化输出和省掉的解析工作。

## 六项发现

1. **空正文根因是 SPA** —— 浙大 `main_text` 仅 4 字，用 `dom/dump` 拿回 88,480 字符 HTML，
   去标签后仍只有 4 字。本地复核：`<body>` 87,546 字符，可见文字 0，含 `id="root"`。HTML 本就没内容。
2. **引擎 panic 可稳定复现** —— 东南、哈工大命中同一行
   `moli-renderer-v8/src/live_document_parser.rs:498:9`，失败耗时 3–4.5 秒（远低于超时）。
3. **links 不全且不可预测** —— 复旦页面 310 个链接平台只给 71 个；返回数在 57~94 之间浮动，
   既不全也没有可预测规则。
4. **正文被选择性丢弃** —— 上交平台 1,865 字 vs 裸抓 2,840 字，句子级比对：
   裸抓独有 19 条、平台独有 3 条。丢掉的是中院、李政道图书馆的整段介绍。
5. **诚实的负结果** —— 平台正文长度 / 裸抓可见文字中位仅 0.98x。
   增值在结构化解构：201 headings / 194 paragraphs / 130 lists / 868 images。
6. **extra schema 不统一** —— 同一字段三种形态（dom_summary / 仅 metadata / 完全缺失）。
   且走渲染引擎的站点平均正文反而更短（约 3,100 vs 约 5,800 字）。

## 方法与可复现性

1. **抓取**：`POST /v1/extract`，20 个站点逐条落盘原始响应 JSON
2. **对照**：3 个站点追加 `POST /v1/dom/dump`，交叉验证正文来源
3. **本地基准**：12 个站点用普通 HTTP 客户端直连，规范化 URL 后逐条比对
   —— **不依赖平台提取逻辑，避免自己验证自己**
4. **数据可信度**：报告每个数字经 `factcheck_v2.py` 与原始响应核对，**45 项全部一致**

> ⚠️ **方法论提醒**：初版比对脚本直接字符串对比 href，因平台把相对 URL 规范化为绝对 URL
> 而误判（北师大、中科大出现"平台返回 > 本地"的矛盾）。修正口径后结论才稳定。
> 这说明验证抓取工具的返回，必须先用独立基准对齐口径。
